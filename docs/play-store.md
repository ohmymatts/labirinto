# Publishing LABIRINTO to Google Play Store

LABIRINTO is a PWA (installable web app with offline support). The
supported, well-trodden path from a browser game to the Play Store is
wrapping it as a **Trusted Web Activity (TWA)** — a native Android shell
that runs your web app fullscreen, no browser UI, packaged as an
Android App Bundle (`.aab`).

What's already done in this repo:

- `manifest.webmanifest` — app identity, icons, standalone display
- `sw.js` — offline cache (whole game works offline)
- `icons/` — 192/512 + maskable icons (generated by `node tools/generate-icons.js`)
- e2e screenshots in `test/screens/` you can reuse for store listing drafts

What only YOU can do (accounts, hosting, signing, payment):

1. Register a **Google Play developer account** (one-time $25): https://play.google.com/console
2. Host the game on a HTTPS URL (see Step 1 below)
3. Package the TWA (Step 2)
4. Publish (Steps 3–5)

---

## Step 1 — Host on HTTPS (free option: GitHub Pages)

The packaged app fetches your site and **requires valid HTTPS** (Chrome 86+
crash policy: no valid TLS → app crashes).

```bash
# inside D:\labirinto
git init
git add .
git commit -m "LABIRINTO v1"
git branch -M main
# create an empty repo on github.com first, then:
git remote add origin https://github.com/<you>/labirinto.git
git push -u origin main
```

Then on GitHub: **Settings → Pages → Source: GitHub Actions (or main branch)**
→ the game is live at `https://<you>.github.io/labirinto/`.
(The service worker and manifest must return HTTP 200 — GitHub Pages does.)

Verify: open the URL in Chrome desktop → DevTools → Application → Manifest:
"Installable", no errors. On an Android phone Chrome will show
**Install app**.

## Step 2 — Package as an Android app (two equivalent routes)

### Route A: PWABuilder (easiest, no local toolchain)

1. Go to https://www.pwabuilder.com
2. Paste your `https://…/labirinto/` URL → it validates the manifest & SW
3. "Package for stores" → **Android**
4. Options: package id `com.labirinto.game`, app name `LABIRINTO`, leave
   "host requirements" pointing at your URL
5. It generates a zip containing:
   - `app-release-bundle.aab` ← upload this to Play
   - `app-release-signed.apk` ← for device testing
   - `assetlinks.json` ← domain-ownership proof
   - `signing.keystore` + `signing-key-info.txt` ← **keep both forever safe**
     (losing them means you can never update the app under the same identity)

### Route B: Bubblewrap CLI (Google's official tool, more control)

Requires Node (you have it) + Java 17 — Bubblewrap offers to install the JDK
and Android SDK automatically on first run.

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest="https://<you>.github.io/labirinto/manifest.webmanifest"
bubblewrap build     # produces app-release-bundle.aab
```

A reference config is provided in `docs/twa-manifest.json` (answers for
`bubblewrap init`; adjust package id / signing as you like).

## Step 3 — Deploy `assetlinks.json`

Upload the generated file to:

```
https://<you>.github.io/labirinto/.well-known/assetlinks.json
```

On GitHub Pages, commit it inside a `.well-known/` folder at the site root.
Without it the app shows a browser address bar or crashes.

## Step 4 — Create the Play Console entry

1. Create app → name `LABIRINTO`, default language, **Game**, free
2. Store listing:
   - Short description (≤80 chars):
     `Find the key. Unlock the door. Escape the maze before the ghosts do.`
   - Full description: reuse the README "How it gets harder" section
   - Graphics: icon `icons/icon-512.png`; feature graphic 1024×500 (ask, or
     generate); screenshots — phone (portrait) recommended, but the
     landscape 1280×820 captures in `test/screens/` are a solid start
3. **App content declarations**:
   - **Data safety**: the game stores only your best level in local storage
     and collects/shares nothing → declare "No data collected, no sharing"
   - **Content rating** questionnaire: mild/fantasy, no gore, no ads →
     expect "Everyone"/"Everyone 10+"
   - **Target audience**: must NOT target children — PWAs cannot target
     children under Google's Families policy; pick older audiences
   - **Privacy policy**: need a URL — template provided at
     `docs/privacy-policy.md` (host it (e.g., in the same repo as Pages),
     and link it)
4. Play App Signing:
   - First upload: use your generated keystore
   - After upload, Google re-signs → copy the **SHA-256 fingerprint** from
     Play Console → `Setup → App integrity` → append it to the
     `sha256_cert_fingerprints` array in `assetlinks.json` and redeploy
     that file (this is what removes the address bar)

## Step 5 — Release

Upload `app-release-bundle.aab` → internal testing track first (install from
the test link on a real phone, play through a few levels) → then promote to
production. Review usually completes within days for small games.

## Updating the app later

- Bump any content change, repackage (bubblewrap build / PWABuilder again),
  upload the new `.aab` as a new **release** using the SAME keystore, and
  bump `versionCode`.
- When changing web assets served to the TWA, bump `sw.js` `VERSION` so
  existing players' cache refreshes.
