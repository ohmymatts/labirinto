# Publishing LABIRINTO to Google Play Store

**Status: the game is DEPLOYED and LIVE at https://ohmymatts.github.io/labirinto/**
(GitHub Pages, `main` branch - republished any time with
`powershell -ExecutionPolicy Bypass -File tools\deploy.ps1 -CommitMessage "...").

LABIRINTO is a PWA (installable web app with offline support). The
supported, well-trodden path from a browser game to the Play Store is
wrapping it as a **Trusted Web Activity (TWA)** - a native Android shell
that runs your web app fullscreen, no browser UI, packaged as an
Android App Bundle (`.aab`).

What's already done in this repo:

- `manifest.webmanifest` - app identity, icons, standalone display
- `sw.js` - offline cache (whole game works offline)
- `icons/` - 192/512 + maskable icons (generated by `node tools/generate-icons.js`)
- hosting: LIVE on GitHub Pages (see top)
- e2e screenshots in `test/screens/` you can reuse for store listing drafts

What only YOU can do (accounts, signing, payment):

1. Register a **Google Play developer account** (one-time $25): https://play.google.com/console
2. Package the TWA (Step 2)
3. Publish (Steps 3-5)

## Step 1 - Host on HTTPS: DONE

Deployed: `https://ohmymatts.github.io/labirinto/`. To re-deploy changes:

```powershell
powershell -ExecutionPolicy Bypass -File tools\deploy.ps1 -CommitMessage "your message"
```

(The service worker and manifest serve with HTTP 200; Chrome desktop
DevTools > Application > Manifest shows "Installable". On an Android phone
Chrome shows **Install app**.)

## Step 2 - Package as an Android app (two equivalent routes)

### Route A: PWABuilder (easiest, no local toolchain)

1. Go to https://www.pwabuilder.com
2. Paste `https://ohmymatts.github.io/labirinto/` - it validates the
   manifest and service worker
3. "Package for stores" > **Android**
4. Options: package id `com.labirinto.game`, app name `LABIRINTO`
5. It generates a zip containing:
   - `app-release-bundle.aab` - upload this to Play
   - `app-release-signed.apk` - for device testing
   - `assetlinks.json` - domain-ownership proof
   - `signing.keystore` + `signing-key-info.txt` - **keep both forever safe**
     (losing them means you can never update the app under the same identity)

### Route B: Bubblewrap CLI (Google's official tool, more control)

Requires Node (you have it) + Java 17 - Bubblewrap offers to install the JDK
and Android SDK automatically on first run.

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest="https://ohmymatts.github.io/labirinto/manifest.webmanifest"
bubblewrap build     # produces app-release-bundle.aab
```

A reference config is provided in `docs/twa-manifest.json`.

## Step 3 - Deploy `assetlinks.json` at the DOMAIN ROOT

Digital Asset Links are validated against the host **origin root**, so the
file must answer at:

```
https://ohmymatts.github.io/.well-known/assetlinks.json
```

Note: this is the domain root, NOT under `/labirinto/`. A GitHub
*project*-Pages repo cannot serve the domain root - the standard fix is a
tiny second repo named `ohmymatts.github.io` (your "user site") containing
just `.well-known/assetlinks.json`; it is then served at the domain root.
The deploy script in `tools/` can create it the same way once you have the
fingerprint (Step 4).

Without a valid assetlinks file the TWA shows a browser address bar
(or may refuse to launch). Alternative without asset links:
`fallbackType: customtabs` keeps the app working but with a browser bar.

## Step 4 - Create the Play Console entry

1. Create app - name `LABIRINTO`, default language, **Game**, free
2. Store listing:
   - Short description (under 80 chars):
     `Find the key. Unlock the door. Escape the maze before the ghosts do.`
   - Full description: reuse the README "How it gets harder" section
   - Graphics: icon `icons/icon-512.png`; feature graphic 1024x500 (can be
     generated on request); screenshots - the landscape captures in
     `test/screens/` are a solid start (portrait 9:16 recommended at upload)
3. **App content declarations**:
   - **Data safety**: the game stores only your best level in local storage
     and collects/shares nothing - declare "No data collected, no sharing"
   - **Content rating** questionnaire: mild/fantasy, no gore, no ads
   - **Target audience**: must NOT target children - PWAs cannot target
     children under Google's Families policy; pick older audiences
   - **Privacy policy**: need a URL - template at `docs/privacy-policy.md`
     (commit it in this repo so it serves at
     `https://ohmymatts.github.io/labirinto/docs/privacy-policy.md`, and
     replace the placeholder contact e-mail)
4. Play App Signing:
   - First upload: use the generated keystore
   - After upload, Google re-signs - copy the **SHA-256 fingerprint** from
     Play Console > `Setup > App integrity` - append it to the
     `sha256_cert_fingerprints` array in `assetlinks.json` and redeploy that
     file (this is what removes the address bar)

## Step 5 - Release

Upload `app-release-bundle.aab` - **internal testing** track first (install
from the test link on a real phone, play through a few levels) - then
promote to production. Review usually completes within days for small games.

## Updating the app later

- Change web content: commit + redeploy (deploy.ps1). Bump `sw.js`
  `VERSION` when players' offline caches must refresh.
- Change the shell (versionCode, icon, name): repackage and upload a new
  `.aab` release with the SAME keystore.
